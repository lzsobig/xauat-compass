# 试用与变现验证

## 首版交付的价值

免费提供公开赛事查询、来源、规则参考、本机收藏与任务管理。限额智能规划用于验证学生是否真的需要按个人兴趣、团队与时间安排备赛。

本轮没有付款入口。以下是待验证的产品假设，不是已经确认的商业结果。

## 先验证三个问题

1. 学生能否独立找到愿意继续了解且可能具备参赛资格的赛事？
2. 四周准备任务是否具体到可以开始，时间预算是否适合真实生活？
3. 学生愿意为什么继续使用：多方案比较、重新排期、作品复盘，还是更深入的赛事资料？

## 首批试用执行

- 由维护者邀请约二十位不同年级、不同经验的学生，每人分配独立试用码。系统不自动替维护者联系任何人。
- 请学生完成一次选赛与规划，保存一项任务，在之后的一周内尝试完成它。
- 使用产品内反馈收集帮助度和改进意见，避免索取学号、密码等信息。
- 每周运行 `npm run report` 查看成功/失败次数、延迟、模型 token、保存、导出及反馈汇总。保存/导出统计仅覆盖有有效试用会话的访问者，不代表全站完整留存统计。
- 当前不采集跨会话访客追踪，也不上传所有本机任务；真实报名或任务完成情况通过自愿访谈确认。

## 付费候选

| 能力 | 用户可能付费的理由 | 开发前需要的证据 |
|---|---|---|
| 多方案比较 | 需要在两个目标或多个赛事间选择 | 用户实际提出不同方案的比较需求 |
| 时间变化后的重新排期 | 课业与团队安排变化，原计划难以执行 | 用户持续回来调整，且现有调整明显不够用 |
| 阶段复盘与进阶报告 | 想知道准备成果是否完整、下一步怎么改 | 用户主动提交真实成果并认可反馈质量 |
| 团队协作与云同步 | 多人协同、跨设备操作 | 单机保存已成为真实使用阻碍 |

基础事实与来源不作为付费墙。不得售卖虚构获奖概率、确定性认定结论或无法交付的提醒能力。

## 成本与定价

先记录真实模型用量和失败重试，再结合选用模型实际账单计算单份有效方案的成本。当前尚无真实模型账单，因此不提出利润、售价或回本承诺。

确认重复使用需求后，再建设账号、服务端权益与订单。付费开发前确定清楚可交付的服务边界、额度规则、支付接入和退款处理；本轮没有模拟付款成功页面。
