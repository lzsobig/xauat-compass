## 视觉调整

根据用户对初版卡片墙的反馈，赛事发现改为连续目录布局：赛事编号与标题为主轴，层级、承办单位、历年参考月份和操作按列排列。去除独立大方卡和无信息价值的大图标。移动端保持连续条目，操作不依赖悬停。

其他页面保留蓝色体系、罗盘路径、规划步骤、分层结果与任务状态反馈。源码集中使用设计变量与运动模块。

## 性能证据的边界

浏览器测试在桌面 Chrome、4 倍 CPU 降速下采集抽屉打开期间 60 个 `requestAnimationFrame` 间隔，具体中位数、P95、最大值见浏览器报告。该采样用于发现明显阻塞，不等于真实手机全流程稳定 60fps 的证明。

本轮检查了手机视口、全屏详情、底部导航和减少动态效果。没有使用实体手机弹出系统软键盘进行验收，也没有进行公网移动网络性能测量。

## 复现

1. 使用 Node 24，运行 `npm run build` 和 `npm start`。
2. 运行 `npm test`。
3. 安装开发依赖 `npm ci`，运行 `npm run test:browser`。
4. 浏览器录像需额外具备 Playwright FFmpeg 并设置 `RECORD_VIDEO=1`；不影响产品运行。
5. 配置真实模型后，兑换本地生成的试用码，执行一次完整生成，确认结果、用量记录及剩余额度。
